# Project workflow rules

1. When starting work on a task, check Git and the latest pull request, then pull the latest relevant changes. Preserve any existing local work; never overwrite or discard it when updating.
2. Make and review changes locally until the user explicitly says they are satisfied. Do not push, open a pull request, or merge before that confirmation.
3. Once the user says they are satisfied, push the changes, open a pull request, and merge it for them. This is standing authorization to perform those steps without asking again. Run the appropriate checks and resolve any failures before merging.
